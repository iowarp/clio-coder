Method

How each page is organized

Every research page follows the same seven parts, so you can compare questions and see at a glance what is still unknown.

  1. The question, stated so that an answer could turn out wrong.
  2. What is known and measured so far, with sample sizes and the build that was measured. A page says when a sample is small, when a result came from a design that no longer exists, and when nothing has been measured yet.
  3. Why the answer matters to people who use coding agents on real projects.
  4. Directions to work on: studies someone could take up, each with what to vary and measure.
  5. How to work on it today with CLIO Coder, using only commands that exist in the stated release.
  6. A first experiment, labelled “proposed, not yet run” until someone has run it and recorded the result on the page.
  7. How to join the work.

Join

Work on a question

Pick a question, run its first experiment or design a better one, and open a GitHub issue describing what you plan to measure. The contributor guide covers setting up a checkout and sending changes. Results, including null and negative ones, are published on the page with their numbers, so the next person starts from what you found.
