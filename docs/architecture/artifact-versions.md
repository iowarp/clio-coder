# Artifact Versions & Serialization Contracts

This document is an operator-facing registry of compatibility-sensitive file
formats, serialized structures, integrity digests, and migration rules in the
current source tree. It is not an exhaustive inventory of every internal store
or wire frame. Source version constants and their readers remain authoritative.

---

## 1. Operator-facing Artifact Registry

Clio Coder gives its compatibility-sensitive persistent and network contracts an
explicit version or schema identity. This table also calls out selected
unversioned stores whose handling matters to operators. Section 2 lists the
remaining named version constants. Small stores that carry only a literal
`version: 1` field, such as `batches.json` (detached batch records),
`agent-ledgers.json`, `cancel-requests/`, `interop.json`, `endpoint-slots.json` and
`harness-profile.json`, are not enumerated; each reader
ignores or refuses a record of another version. Depending on the artifact, an
incompatible reader fails closed, skips an invalid record, or uses an explicitly
documented compatibility normalization.

## 3. Integrity Verification Contracts

### Sealed telemetry scopes

A telemetry scope's journal is hash chained line by line, and closing the scope appends a `session.sealed`, `run.sealed` or `process.sealed` record over the chain head and writes `bundle.json` beside it ([seal.ts](../../src/domains/telemetry/seal.ts)). The chain is unkeyed: it catches corruption and edits that leave it stale, not a writer who rewrites the journal and recomputes every link.

`verifyTelemetryScope` checks, in order:
1. `bundle.json` is a version 1 `clio-coder.telemetry.bundle`; a scope without one is unsealed, not failed.
2. Every segment and object the manifest lists exists with its recorded SHA-256 and size, and each object's name matches its digest.
3. The chain walks unbroken from the first segment to the seal, the seal is the last line of the live segment, and its object list and share profile agree with the manifest.
4. The manifest's chain head, `sealedAt`, host and `clioCoderVersion` match what the chain and the sealing segment's header committed.

`clio-coder telemetry verify` runs this over a scope directory or every scope in a share archive. See [Telemetry](telemetry.md#verify).

## 4. Migration Mechanics

Session format handling runs automatically when a session is opened:

1. **Discovery**: `src/domains/session/migrations/index.ts:runMigrations` reads the recorded `sessionFormatVersion`, treating a missing field as version 1.
2. **Readable range**: This build reads versions 3 to 6. A missing format or version below 3 is refused; a version above 6 is refused with upgrade guidance.
3. **Additive step**: Versions 3 to 5 open as version 6. The chain adds working-set records (v4), continuity records and checkpoint payloads (v5), and eviction reasons, reread triggers, and content hashes (v6). Existing `current.jsonl` and `tree.json` content is not transformed.
4. **Metadata update**: The session metadata is restamped with `sessionFormatVersion: 6` through the session writer's normal durable path.
