One System Prompt Per Session

The chat loop compiles one provider-facing system prompt per session. The compile key is target|model|autonomy|sessionId|workingContextPaths, with paths sorted before hashing into the key.

The compiled prompt is reused byte-for-byte on ordinary submissions. When path-scoped project rules trigger a recompile, the session ledger records a promptRecompiled entry with previous/new hashes and token estimates.

Dynamic User Message Ordering

Variable task context is delivered via structured, dynamic user messages rather than system prompt mutations:

1. Project Context (CLIO-CODER.md / codewiki summary)
2. Safety Posture Reminder (action-class rules)
3. Memory Injections (approved task bank / lessons)
4. Dispatch Briefing (bounded, untrusted data envelope, ≤12KB)
5. Pipeline Input (upstream worker artifacts)
6. Operator Task Prompt (user's submitted task)

Prompt Template Expansion ($1..$9, $@, $ARGUMENTS)

Shell-Style Parameter Parsing

Templates expand into the operator's message prior to submission:

  • Single and double quotes preserve whitespace within arguments.
  • $1 through $9 bind to positional arguments.
  • $@ and $ARGUMENTS join all arguments with single spaces.
  • Unsupplied positional parameters expand to empty strings.
  • Collisions with built-in slash commands fail closed and are excluded from /prompts.

Template Expansion Example

# Template body:
Review PR #$1 on branch $2 with flags: $ARGUMENTS

# Invocations:
/review 104 feat/auth --verbose
# Expands to:
Review PR #104 on branch feat/auth with flags: 104 feat/auth --verbose

Directory-Scoped Handbook Overrides (`CLIO-CODER.override.md`)

Subtree Isolation Boundaries

  • CLIO-CODER.override.md replaces inherited root instructions for its directory and all subdirectories.
  • Sibling directories outside the subtree continue to inherit from the root handbook or their own local overrides.
  • Subdirectories within the subtree may supply narrower instructions with additional override files.
  • Prompt blocks preserve explicit source paths for provenance.
  • Malformed override files fail closed; context resets never delete override files.

The Observation Envelope (OBSERVE Tools)

Envelope Guarantees

  1. One Notice Line: [<tool>: <shown>/<total> <unit> shown (<shownSize> of <totalSize>) | full: <offloadPath> | next: <exact-call>]
  2. Offload on Truncation: Spills complete output to <stateDir>/scratch/<sessionId>/<toolCallId>.txt.
  3. Always-Valid JSON: Over-cap JSON is replaced by a parseable stub: {"error":"result exceeded cap","offloadPath":"...","next":"..."}
  4. 192 KB Turn Budget Pool: Shared across all 6 envelope tools per turn; prevents context exhaustion.
