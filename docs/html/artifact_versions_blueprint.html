Cryptographic Receipt Integrity (Version 15)

Canonical Digest Calculation

Receipt integrity guarantees that execution facts, token counts, tool outputs, and validation grounding were sealed authoritatively by the orchestrator:

export function computeReceiptDigest(receipt: RunReceiptV15): string {
  const canonical = serializeCanonicalReceipt(receipt);
  return createHash("sha256").update(canonical, "utf8").digest("hex");
}

Sealed Integrity Checks

  1. integrity.version === 15
  2. Calculated SHA-256 digest matches integrity.digest
  3. All optional blocks (validationGrounding, capabilityMismatch, steering, gate, plan, briefing) strictly conform to v15 schema.

Automated Session Migrations

When resuming a session via /resume whose meta.sessionFormatVersion < 3:

Sequential Migration Pipeline

  • Discovery: runMigrations reads recorded format version.
  • Step Execution: Runs sequential passes (v1 → v2, v2 → v3), transforming current.jsonl and updating tree.json.

Atomic Commitment

Staged migrations are written to temporary files, fsync'd, and atomically renamed over the original session directory before meta.sessionFormatVersion is updated to 3.
