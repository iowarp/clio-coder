Overview Summary

Clio Coder manages compute capacity across local and remote nodes using durable leases in dispatch-admission.json protected by a cross-process lock (dispatch-admission.json.lock), heartbeat expiration, and OS process birth tokens.

Admission Workflow

1. Dispatch Request arrives
2. Acquire Cross-Process Lock: dispatch-admission.json.lock
3. Lazy Reap Expired Leases & Dead PIDs (using OS processBirthToken)
4. Check Global & Node Capacity Limits
5. Grant CapacityLease & Write Atomically (version 2)
6. Release Lock and Spawn Worker Subprocess

Drain & Emergency Controls

Maintenance Drain

clio-coder fleet drain refuses new dispatches while allowing active runs to settle. Drain auto-expires in 1 hour if not resumed.

Dead-PID Reaping

Process birth tokens prevent lease leaks from terminated or recycled PIDs by validating OS process state during admission.
