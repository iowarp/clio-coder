Fleet Dispatch v0.3.0 Overview

Clio's Fleet Dispatch orchestrates bounded agents across local processes and remote HPC nodes via SSH transport. In v0.3.0, dispatch includes process-safe capacity leases, WorkerSpec v3 attestation, ExecutionPlan v2 DAGs, Contract v4 per-step write boundaries (detect-and-rollback), bounded check/repair loops, deterministic code steps, strict receipt integrity v15, measured shadow routing, readiness-gated active routing, transactional editing attempts, and bounded agent automation.

Advisory Scout Reconnaissance & Bounded Synthesis

The operating contract steers explicit broad repository exploration to the read-only Scout recipe. After nine or more manual read-only exploration calls without a successful Scout dispatch, middleware emits a continuation nudge; direct reads remain allowed.

orchestrator$ clio dispatch --query "explore repository architecture and dependencies"
[dispatch] evaluating task profile: broad reconnaissance query detected.
[dispatch] broad exploration is advisory-routed to the read-only Scout recipe.
[middleware] 9+ manual read-only calls without Scout: continuation nudge emitted.
[scout-1] launched on node-login-01 (SSH). Exploration budget: 18 calls; read reserve: 4.
[scout-1] synthesis phase: text-only handoff with live path:line citations.

Typed Failure Taxonomy & Failover Attribution

When worker dispatches fail, the coordinator classifies termination evidence and applies assignment-aware retry policy without corrupting session state. Target cooldowns and node offline state are separate mechanisms; there is no generic circuit-breaker state in the public fleet registry.

Representative policy rows are shown below; the complete 13-class matrix is documented in Worker Dispatch Mechanics.

Failure Class Trigger Cause Failover Action Retry / Node State
node-channel Heartbeat dead/stalled, spawn failure, or SSH exit 255 Retry with `node` excluded Offline after 2 consecutive channel failures
target-rate-limit HTTP 429 or rate-limit diagnostic Retry with `target` excluded after 1s minimum Target cooldown (default 15s; configurable)
deterministic-task Typed terminal outcome code No retry; preserve the attempt receipt No breaker action
