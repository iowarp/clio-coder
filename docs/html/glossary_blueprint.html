Overview Summary

Precise definitions for domain terms across fleet dispatch, execution scheduling, receipts, and context engineering, mapped directly to their source TypeScript interfaces.

Fleet & Dispatch Vocabulary

1. Assignment
src/domains/dispatch/assignment-store.ts: DurableAssignmentRecord

The logical unit of work dispatched to the fleet. Encapsulates requested task, briefing, authority boundaries, and retry history across one or more concrete run attempts.

2. Run
src/domains/dispatch/types.ts: RunEnvelope

A concrete execution attempt of an assignment. Every run possesses a unique UUIDv7 identifier, isolated event stream, designated execution node, and final cryptographically sealed receipt.

3. Receipt
src/domains/dispatch/types.ts: RunReceipt (RUN_RECEIPT_INTEGRITY_VERSION = 15)

An immutable, cryptographically sealed record of a completed run containing full execution facts, tool telemetry, token accounting, validation grounding, and outcome codes.

4. Topology
src/domains/dispatch/execution-plan.ts: ExecutionPlanTopology

The multi-agent structural orchestration pattern governing workflow execution: parallel, sequential, pipeline, review, compete, and fleet.

Safety & Execution Vocabulary

5. Posture (Autonomy Level)
src/domains/safety/autonomy.ts: AutonomyLevel

The active safety permission level governing tool mutation authority (read-only, suggest, auto-edit, full-auto).

6. Capability Class
src/domains/agents/spec.ts: AgentCapabilityClass

The maximum permitted mutation boundary declared by an agent recipe (read-only, verification, artifact-write, workspace-edit).

7. Origin Glyphs (◇ / ◆)
src/domains/session/entries.ts: WorkerRunOrigin

Indicators identifying who requested a run: ◇ marks operator-typed runs, ◆ marks model-requested dispatches, and a dim dot marks internal Clio runs.
