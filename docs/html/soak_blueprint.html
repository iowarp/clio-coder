Soak Benchmark Blueprint

Interactive specification and invariant reference for Clio soak suites (v0.3.5)

v0.3.5 Machinery Invariants

Core Principle: Measuring Clio, Not the Model

Every standard evaluation suite measures model capability and only incidentally touches Clio. The soak suite inverts that relationship. A weak model that never solves the task passes if the machinery behaves; a strong model that solves the task fails the moment Clio fails to seal a receipt, cannot authenticate one, or violates a system invariant.

The 4 Soak Suites

clio-soak.yaml
Machinery Under Load

Compares the headless main-agent surface against a dispatched worker surface across single-file and multi-file bug fixtures, plus compaction continuity.

  • Tasks: single-file-bug.main-agent, single-file-bug.dispatch, multi-file-bug.main-agent, multi-file-bug.dispatch, compaction-continuity.main-agent.
  • Gate Invariants: receipt.sealed == true, receipt.integrityValid == true, receipt.outcomeMatchesExit == true, tokens.measured == true, stream.cumulativeSnapshots == 0, stream.usageDoubleCounted == false, stream.segmentUsageMatchesMessages == true.
clio-soak-boundary.yaml
Write Boundaries

Tests per-step write boundary enforcement without model participation. Enforcement is detect-and-rollback, never sandboxing.

  • Tasks: write-boundary.rolled-back (clean detect and git restoration), write-boundary.rollback-incomplete (honest reporting when prior bytes were dirty before snapshot).
  • Task Assertions: boundary.verdictCount == 1, boundary.verdictSealed == true, boundary.violationsDetected == 1, boundary.violationsRolledBack, boundary.rollbackIncomplete.
clio-soak-chaos.yaml
SIGINT Fault Injection

Fault injection testing for process interrupt signals mid tool execution.

  • Tasks: chaos.sigint-mid-tool. Prompts Clio for a long-running tool, injects SIGINT once child process initializes, verifies exit code 130 and zero orphaned children.
  • Task Assertions: chaos.exitCode == 130, process.orphanedChildren == 0, receipt.sealed == true, receipt.integrityValid == true, tokens.measured == true.
clio-soak-loop.yaml
Bounded Loops

Gates iteration bounds and receipt usage accounting for fleet repair loops.

  • Tasks: bounded-loop.fleet.
  • Task Assertions: loop.attemptsSpent <= 3, loop.receiptsMatchRepairs == true, loop.skippedNodes == 0, receiptUsage.measured == true.
  • Token Accountings: Demonstrates difference between tokens.* (wire streaming; false on fleet runs) and receiptUsage.* (authenticated journal receipts; true).

Three-Layer Metric Classification

Layer Source / Location Role & Behavior
verify.measure Task definition in YAML Records whether the model solved the task (task.solved, task.exitCode). Nonzero exit is recorded and never fails the item.
thresholds.fail Suite-wide thresholds Gates universal promises (receipt sealing, receipt integrity, outcome consistency, token reporting). Unmeasured metrics fail closed.
verify.assertions Per-task verify section Gates surface-specific promises (session ledger invariants for main-agent, process group cleanup for workers, boundary verdicts).
