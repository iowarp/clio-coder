The Three Audiences Rule

Every file Clio generates has exactly one home based on who reads it. The core principle: the repo working tree holds only files a human asked for.

Audience Category Definition & Intent Destination Root
Human Deliverable Files the user explicitly requested, will read, commit, and ship. Working tree, at the exact path requested by user.
Human Transient Reports, plans, or evidence an operator reads once; losing them costs nothing. Project-local .clio-coder/ (gitignored) or XDG roots.
Agent-to-Agent State Machine plumbing between turns, workers, and sessions (codewiki, handoffs, ledgers). .clio-coder/ for per-repo state; XDG data/state/cache for machine state.

`.clio-coder/` and Git Negations

.clio-coder/ is gitignored by default. To share authored project rules, fleet contracts, or safety policies, use explicit un-ignore negations:

.clio-coder/
!.clio-coder/fleets/          # Shared fleet contracts
!.clio-coder/fleets/**
!.clio-coder/rules/           # Path-scoped project rules
!.clio-coder/rules/**
!.clio-coder/safety.yaml      # Project safety policy
!.clio-coder/agents/          # Custom project agent recipes
!.clio-coder/agents/**
