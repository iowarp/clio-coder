## Target design inside Clio

Keep `gateway` as the proxy. Keep `mcp_<id>__<tool>` as the capability identity. Make discovery metadata independent of executable registry specs.

Change these existing files:

- `src/tools/gateway/mcp-capabilities.ts`: separate catalog access from `ensure()`; load valid cached descriptors for discovery; publish metadata after successful live discovery. Keep connection deduplication, `makeSpec()`, trust-derived authority, result shaping, and teardown ownership here. Add a metadata lookup for describe and an explicitly scoped discovery operation. Keep `ensure()` as the live execution seam.
- `src/tools/gateway/index.ts`: make ordinary find consume cached or already-live metadata without launching processes. Merge those entries with existing builtin and extension entries, deduplicate by capability name, and retain query filtering, sorting, entry caps, and observation accounting. Make describe consume metadata without requiring registration. Keep call resolving a live MCP spec before argument validation and nested registry admission.
- `src/domains/gateway/mcp/index.ts`: export only the cache types and helpers the capability source needs.

Add `src/domains/gateway/mcp/metadata-cache.ts` and focused `node:test` coverage in `tests/contracts/mcp-metadata-cache.test.ts`. Extend `tests/contracts/gateway-mcp.test.ts` and relevant existing gateway contracts after reading them. Do not create another client or server manager. Keep `src/domains/gateway/mcp/client.ts` unchanged unless a narrowly justified decoder extraction is necessary; its framing, handshakes, pagination, timeouts, and process-group cleanup already solve the transport problem. Keep `config.ts` and `trust.ts` behavior intact.

Use this discovery contract:

- Ordinary find and describe must work from a valid cache without any client construction. Label catalog provenance separately from connection status. A cache hit must never report a connected server.
- On a cold, invalid, or expired cache, find returns declared server summaries with an explicit missing-catalog state. It must not quietly launch all trusted servers. Describe returns a targeted discovery remedy if that tool's metadata is unavailable.
- Add optional `server` and `refresh` inputs to gateway find. `gateway(op="find", server="<id>", refresh=true)` performs scoped live discovery and updates that server's cache. Reject refresh without a server, refresh for an undeclared server, and these inputs on other operations. Do not add reconnect behavior for servers that already failed in the session.
- A known capability may still be called directly through gateway without a cache. Resolve its owner, discover that owner live, validate against the live schema, and invoke through the registry. An unknown or removed live tool must fail rather than executing through stale metadata.
- Preserve restricted-surface behavior. A caller with `allowedTools` or turn constraints must not use refresh to launch servers outside its authority. For this slice, reject explicit refresh on a restricted surface, matching the existing suppression of broad discovery. Continue to allow admitted exact capability calls through the existing path.
- Keep server summaries compact. Do not copy every cached tool name into each server's `tools` array as well as the filtered capabilities list. Preserve trust remedies, diagnostics, and catalog truncation information within the existing observation boundary.

Persist bounded, validated descriptors and completeness information. Derive cache identity from the canonical project root, declaration scope and source, server id, declaration digest, and resolved execution cwd. `mcpServerDigest()` at `src/domains/gateway/mcp/config.ts:112-134` alone does not bind a relative declaration to its resolved project location. Never persist environment values, launch credentials, trust decisions, or executable closures. Recompute authority from Clio trust records.

Treat malformed, unsupported, oversized, expired, or mismatched cache entries as misses. Use bounded regular-file reads, atomic writes, and explicit byte and entry limits. Reuse `readBoundedFileText()` at `src/domains/gateway/mcp/config.ts:387-420` and inspect Clio's existing atomic resource writer before choosing the write seam. Keep cache write failures nonfatal to live tool use. Choose and document an expiry constant; test expiry with an injected clock. Use isolated cache entries or another explicit strategy that prevents concurrent sessions from overwriting unrelated servers' metadata. Do not blindly copy the reference's shared-file merge.

## Traps to test explicitly

- **Cached registration breaks the present lookup contract.** `src/tools/gateway/index.ts:156-162` calls `ensure()` only when the registry lacks the name. `connect()` at `src/tools/gateway/mcp-capabilities.ts:317-324` refuses an already registered name. Pre-registering cached specs would skip live setup and prevent live replacement. Keep cached descriptors separate from registry entries.
- **Admission belongs to the capability.** Gateway validates the inner schema and invokes the registry under the inner name at `src/tools/gateway/index.ts:307-325`. It strips the gateway's one-shot approval before nesting. Never invoke `client.callTool()` directly from a new gateway discovery or proxy handler. Keep `details.capability` for evidence consumers.
- **Trust is not a metadata field.** User-scope declarations are trusted by authorship with unknown action class; project trust binds the declaration digest at `src/domains/gateway/mcp/trust.ts:161-178`. `makeSpec()` derives action class from that trust and projects execute-class launch vectors to the shell classifier at `src/tools/gateway/mcp-capabilities.ts:215-223,274-282`. A cached description or annotation cannot confer authority. Resolve current trust when a new source opens a cache. The current source snapshots declarations for a session; do not silently claim hot revocation or add it here.
- **Names have ambiguous separators.** `ownerOf()` at `src/tools/gateway/mcp-capabilities.ts:382-395` chooses the longest declared server prefix, including untrusted declarations, because ids and tool names can contain `__`. Cache indexing and scoped discovery must use this same ownership rule. Do not split on the first separator or let cache load order choose authority.
- **Cancellation is shared.** `discover()` at `src/tools/gateway/mcp-capabilities.ts:336-353` closes the shared pending connection on abort, affecting other waiters. Preserve this behavior. Do not publish a successful cache from aborted or failed discovery. A truncated successful listing must remain explicitly incomplete.
- **Failures are sticky and process ids are owned.** The source blocks reconnect after failure; the client releases group ownership after teardown and must never signal a recycled id. Do not transplant reference retry or idle timers into the client. Preserve exit cleanup and incomplete-teardown reporting.
- **A valid cache is still only a snapshot.** Live schema validation on first call remains mandatory. The client exposes `toolsChanged()` at `src/domains/gateway/mcp/client.ts:638-640,915-919`, but the capability source does not consume it. Do not claim dynamic catalog convergence. Defer notification-driven refresh and document that active-session metadata remains a snapshot.
- **Discovery already has output controls.** Retain the reservation and `finalizeObservation()` path rather than adding an independent byte truncator. The exact observation envelope implementation was not read; inspect `src/tools/observation.ts` and `src/tools/gateway/caps.ts` before changing its contract. Preserve MCP call output bounds at `src/tools/gateway/mcp-capabilities.ts:20-21,230-239` separately from discovery output.
