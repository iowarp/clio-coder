The release-blocking defect this area found: fleet admission double-counted the fleet's own held reservation. The admission seam forwarded a reservation to the capacity controller only when the request had no lineage; fleet requests always carry lineage, so admission acquired a second slot beside the fleet's own held member and a one-slot endpoint refused every fleet, one-step included, from a fresh home, with a message falsely blaming "the orchestrator's own turn". The rt-4b follow-up proved it with a `maxConcurrentRequests: 2` override admitting the identical fleet, ruled out stale holds and cross-process residue, and located the guard. Fixed in `8916ddca`: the first attempt transfers the held member into the lease, refusals name the actual holders, and the member lifecycle (`consumedAt`/`releasedAt`) completes. #256 (council admission) was confirmed adjacent but distinct and stays deferred to v0.4.0.

## Fix loop during the test

Two fixer sessions ran in `clio-coder-wt/release-fixes` (`wip/release-fixes`), one issue per session, each landing on `v0.3.9` by reviewed cherry-pick with the full lanes-5 suite, typecheck, lint, and build green in the worktree first:

1. `fc832214` `fix(tui): render preparation and compaction states (#251)`. The chat loop now awaits a presentation barrier (`chatRenderer.flushAndCommit`) that commits the pending row, `PREPARING` rail, and preparing footer before admission work starts; compaction activity emits a real `compact` phase instead of `done` from the first frame. New contracts drive the production slash runtime and renderer and fail on the old code.
2. `8916ddca` `fix(dispatch): transfer fleet reservations into leases`. First-attempt fleet requests transfer their held reservation member into the capacity lease; refusal messages name the actual occupancy addends; reservation members settle with real `consumedAt`/`releasedAt`. New fleet-v5 contracts prove a one-step fleet admits on a one-slot endpoint and a genuine same-wave 2-on-1 still refuses.

## Observations for triage (not blockers)

- A headless `clio-coder run "/unknown-token"` forwards the token to the model as an ordinary task; `docs/extensions-and-sharing.md:74` promises an `is not a command` refusal. A mistyped slash command spends a model turn. (rt-5)
- Once `t` opens ask_user's text field, that question stays in text mode; Esc cancels the whole interview rather than returning to the option list, so a single-question round has no route to discard typed text. (rt-3)
- A fresh headless process does not reuse discovered `parallelSlots` (mini advertises 4; a new process falls to the local-native default of 1 unless `maxConcurrentRequests` is set). Cross-process capacity discovery is a design gap, reported by the admission fixer. (rt-4b)
- The compaction command is `/context compact`; `/compact` is not a command. (rt-1)
- LM Studio reports no `timings`/cached-token split on its OpenAI-compatible port, so `/context` renders `cache read n/a` on dynamo; accounting stays honest. Known from #247's sprint finding. (rt-1)

## Re-verification against the rebuilt tarball

The final candidate `8916ddca` passed the full gate (`npm run ci:release`: 5,263/5,263 tests at 8 shards in 204.0 s, trace-viewer green, all 26 behavioral machinery scenarios matching the checked baseline, `check-release: ok` at 1,290 files, 6.77 MB packed / 39.14 MB unpacked). The tarball was rebuilt (sha256 `72fd40a66aa1f99fe24250355d1ec8a45378c0d2d68293a74412aef68af6b33a`) and reinstalled into the same clean prefix.

- Admission (`8916ddca`): the exact one-step fleet that deterministically refused from the untouched `home-dispatch-rt4b-fresh` home now exits 0 against the reinstalled binary, and the durable verdict `write-boundaries/fleet-f18a3b3702cc/wave-0.json` reads `status: clean` with two `attributionDowngrades` naming `bash` (`opaque_tool_succeeded`), closing rt-4's #236 row end to end.
- Rendering (`fc832214`, report `rt-1b-reverify.md`): 2/2 PASS. Across three turns and 2,491 polls, every submit painted a frame with the `PREPARING` rail and placeholder, the `· preparing` user row, and the previous turn's receipt dropped (preparing frames at t=37-49 ms). The 3.8 s `/context compact` run showed a live `compact` spinner at 0% in all 16 running frames, with `done` and 100% appearing only at the t=3,800 ms completion frame and the `/context init` stage strip in no frame. The `COMPACTING` composer rail is wired on the same pre-submit path but was not reached live, because nine turns under two forced-threshold configurations always fired auto-compaction after admission; the fixer's own live verification during a forced pre-submit summary did capture the `COMPACTING` rail and placeholder.
