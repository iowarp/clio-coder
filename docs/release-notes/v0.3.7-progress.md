## Decisions made during implementation

- #155 reconciliation: the model-facing request gains one `intent` object
  (`read_roots`, `write_roots`, `relevant_paths`, `expected_outputs`,
  `verification: [{check, timeout_ms?}]`). `gate: "<check>"` is the only
  shorthand and expands to one verification entry. There is no separate
  top-level `verify` field. A `check` is a declared id resolved through the
  verify tool's `DeclaredCheck` projection at admission; model text never
  becomes argv. Verification executes on singular, parallel, sequential,
  pipeline, and detached runs in this cut; review and compete accept the
  intent shape but refuse verification entries with a named reason.
- Receipt integrity version moves 15 to 16 with the `verification` field.
