## Deviations from the charter

- The operator's `feat(workbench)` commit (2053d42d) landed on `v0.3.9` mid-sprint and is v0.4.0 scope. It was moved to branch `feat/workbench` with its own worktree, and `v0.3.9` was rebased without it before any push, so brief hashes after brief 06 changed once. The Codex pane working on the workbench continues on that branch.
- `/tmp` on the build host is a 4 GB tmpfs and was 95 percent full with the 0.3.8 release-test scratch trees (`clio-v038-*-prefix`, `clio-v038-fixed-source`, `clio-v037-upgrade-prefix`, 2.4 GB, none open by any process). Every full test run under that condition failed with `ENOSPC` inside CLI smoke tests; the four trees were removed on 2026-08-29 before brief 01's verification run.

- The charter's baseline step 1 asks for the eval suite brief 02 names, run three times by hand before brief 02 lands. No suite file exists in the tree at `7e1e20ae` (only run artifacts under `benchmarks/internal/runs/`), so there is nothing to run by hand. The interactive-session and fleet measurements of the baseline are taken as soon as wave 1 merges. The eval-suite measurement is taken after brief 02 merges and before briefs 04, 05, 06, and 07 merge; brief 02 is measurement machinery and moves no prefill number, so the baseline it produces is still a "before" for every brief that does.
- The operator's default orchestrator target `dynamo` is LM Studio on a Windows machine (192.168.86.143:1234), a wrapper over llama.cpp that is far less configurable. The operator directed the sprint to stay on native llama.cpp, so the baseline, the after, and every live check run against `mini` (192.168.86.141:8080, build `b226-2115b73d8`, model `qwen3.8-27b-dense`) with `--target mini`. LM Studio is checked only for the `timings` shape in brief 01.
- The eval suite's first after-run died on `ENOSPC`: `eval run --trials 3` copied the workspace into the 4 GB tmpfs once per trial, and the main repo carries 1.4 GB of gitignored benchmark datasets that the baseline's snapshot worktree did not. The after-run was redone from a clean worktree of `v0.3.9` at `18524b69` with `TMPDIR` on disk, and `8c6aa410` makes the runner copy the git-visible set only, one trial at a time, cleaned on failure.
- Reading the baseline artifact showed `summary.passed` (26) disagreeing with the verdict aggregates (23); the code grader's outcome was not part of `result.pass`. `8c6aa410` makes one pass rule, and both eval sections report the grader's figure.
- An independent review of the merged branch (report 11) found and fixed two defects at the hand-resolved seams (`382b1853`) and one in the memory tier's cold-reason path (`df8e6d8b`). Two observations were left as recorded: after an in-process `/resume`, `previousHash` names the abandoned session's hash in the new session's manifest (provenance only; the cold-reason stamp is right either way), and `preferLoaded` in `ensureSessionPrompt` is unreachable.
- The GitHub milestone `v0.3.9` holds 23 open issues beyond the sprint's eight; the eight are closed with their local commit named in the closing comment, and the branch is not pushed.
- Final `npm run ci` on `v0.3.9` at `20aac847` (code identical to the docs-only tip): exit 0, 5147 tests passed across the suite and the trace viewer.
