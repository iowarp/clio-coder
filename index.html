A coding agent for
scientific software.

Clio Coder reads, edits, and runs checks in your repository
with the models you choose, from the terminal or a local desktop app.

Developed for simulation kernels, numerical libraries, data pipelines, and mixed-language builds. It works for everyday software too. Open source under Apache 2.0.

01 / Understand

Understand a repository
before changing it.

Clio Coder reads files, searches the tree, inspects Git history, and navigates a Tree-sitter codemap of your project. Ask it to find the entry points, trace a calculation, or explain how the project builds and tests. A CLIO-CODER.md handbook and layered rules give it standing project context.

“Explain how this repository builds and runs its tests. Find the main entry points. Do not change files yet.”

02 / Change

Make the change
within the scope you set.

Fix a calculation, investigate a failing check, or implement a feature. Clio Coder edits files and runs commands in your project. The default policy allows workspace edits and recognized checks, and asks before unfamiliar commands and outward actions such as a push. Every tool call and diff is recorded for review.

Permissions
Permission cards show the exact invocation. Deny skips a call; Stop ends the turn.
Steering
During a turn, Enter steers, Ctrl+Q queues a follow-up, and Escape interrupts.
Record
The session ledger keeps tool calls, diffs, checks, and cost. Inspect it with /view and /usage.

03 / Delegate

Delegate bounded tasks
to workers.

Hand a side task to a worker while the main conversation continues. Each worker runs a recipe with declared tools, scope, and model, and returns a result you can inspect. Workers run on your machine or on configured SSH nodes that see the project at the same absolute path.

A / “Trace how the input file reaches the solver. Report paths and line numbers. Do not edit files.”

B / /run verifier Review the current diff and run the relevant existing checks. Do not edit files.

Workers and fleets guide →

04 / Verify

Verify with the project’s
own checks.

Ask Clio Coder to run declared tests, builds, numerical comparisons, and performance checks. Results are recorded with their exit status and linked to the change. A repository quality policy can map changed paths to required checks, and completion reports which of them still lack fresh evidence. You review the diff and results before keeping them.

05 / Interfaces

In the terminal
or on the desktop.

Both interfaces run the same Clio Coder runtime and share your saved connections and settings. The terminal is the primary interface. The desktop app opens locally in your browser and is in alpha.

Conversation, tool calls, permission cards, worker activity, and context accounting in one keyboard-driven workspace. Launch it from your repository.

clio-coder

Project and conversation views, session controls, traces, evidence, and configuration. The Artifacts panel holds recorded file activity, results, and linked evidence. The alpha covers a subset of terminal workflows.

clio-coder gui --open

06 / Models

Connect local, institutional,
or cloud models.

A saved model connection is a target. Chat and workers can use different targets, models, and thinking settings, and /model changes the current session. Context windows and capabilities come from the live inference server first, then from packaged model profiles. An unknown window is shown as unknown.

08 / Install

Install Clio Coder
and connect a model.

You need a model with tool calling. Linux and macOS are the primary platforms. The installer brings its own Node.js 24, needs no root, and works on HPC login nodes.

Installation & update guide →Install on a cluster →
1 / Install
curl -fsSL https://coder.iowarp.ai/install.sh | sh

On x64 Linux it works with glibc as old as 2.17. With your own Node.js 22.19 or newer, npm install -g @iowarp/clio-coder works too.

Until 0.6.0 is published, the installer installs 0.5.9. From 0.6.0, native Windows, which is best effort, can run irm https://coder.iowarp.ai/install.ps1 | iex; use WSL until then.

2 / Connect a model
cd /path/to/your/project
clio-coder configure

Guided setup connects an app on this computer, a model server, an AI subscription, or a provider account, and lets you pick from the model list. The desktop app offers the same setup.

09 / Questions

Common questions.

Do I need a Clio Coder account?

No. Clio Coder runs locally with your own model connections. Your cloud provider may require credentials and charge for inference.

Can I use a local model?

Yes. Connect a supported server or compatible API endpoint. Choose a model that supports tool calling. The connection guide covers setup.

What can Clio Coder change on my machine?

Clio Coder can edit files and run commands, subject to its configured permissions. Commands in your own session run with your user’s access and are not sandboxed. On Linux, dispatched native workers can run their commands in a bubblewrap sandbox when one is available. Review permissions and changes as you work.

Is System One on by default?

No. System One is experimental and stays off until you bind a decision site to an engine: a hosted decision engine, a self-hosted systemone server, or a configured chat model. A hosted engine receives redacted request text and bounded tool output. A local server keeps that data on your machine.

How mature is the project?

Clio Coder is pre-1.0 software under active development. The terminal is the primary interface; the desktop is an optional alpha. Report an issue if you run into trouble.
