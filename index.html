01 / From question to checked change

Stay close to the work.

Clio reads your repository, uses its tools, and helps you follow a change through to verification.

  1. 01

    Understand the code

    Find the entry points, trace a calculation, or ask how the project builds. Start with the code already in front of you.

  2. 02

    Work through a change

    Ask Clio to edit, investigate a failure, or delegate a focused task. Review tool activity and the resulting diff.

  3. 03

    Check the result

    Run the project’s tests, builds, or numerical comparisons. Inspect recorded results and see which checks still need your attention.

↗ 07

System One decisions Experimental

A decision engine answers typed questions with probabilities before a turn, on tool calls and results, after a turn, and when ranking catalogs, answering a consultation, or judging drafts. Sites that guide the turn run in shadow, changing nothing, until cuts are fitted for the answering build. An unbound or failed site leaves your workflow as it was.

↗ 08

Drafts & decision records Experimental

/draft N <request> writes N candidate answers in parallel for a bound engine to judge. Turn on systemOne.record to keep redacted decision records on your machine, and read them with clio-coder systemone status or export. clio-coder doctor shows each site’s binding.

On x64 Linux it also works with glibc as old as 2.17, common on HPC login nodes. Until 0.6.0 is published, it installs 0.5.9. 06 / Before you begin

A few practical details.

Do I need a Clio account?

No. Clio Coder runs locally with your own model connections. Your cloud provider may require credentials and charge for inference.

Can I use a local model?

Yes. Connect a supported server or compatible API endpoint. Choose a model that supports tool calling. The connection guide covers setup.

What can Clio change on my machine?

Clio can edit files and run commands, subject to its configured permissions. Commands in your own session run with your user’s access and are not sandboxed. Dispatched native workers run their commands in an OS sandbox when one is available. Review permissions and changes as you work.

Is System One on by default?

No. System One is experimental and stays off until you bind a decision site to an engine: a hosted decision engine, a self-hosted systemone server, or a configured chat model. A hosted engine receives redacted request text and bounded tool output. A local server keeps that data on your machine.

How mature is the project?

Clio Coder is pre-1.0 software under active development. The terminal is the primary interface; the desktop is an optional alpha. Report an issue if you run into trouble.
