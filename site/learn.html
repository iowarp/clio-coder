A field manual

Do the work
in the open.

Ten practical workflows, from your first local model to an independently checked numerical result. Follow the written labs now; recordings will appear here as they are published.

00

Prove the install

Before a model is involved, the binary should answer, and doctor should be able to look without writing.

clio-coder --version
clio-coder doctor
clio-coder paths

Plain doctor is read-only. If you are upgrading and Clio Coder refuses to start, your user settings.yaml still has a retired autonomy name. See Install.

01

A question that cannot edit

Open a repository you know. Ask for a map, and say the boundary out loud.

Explain how this repository builds and runs its tests. Find the main entry
points and suggest one useful verification task. Do not change files yet.

Watch the tool calls. If a command is unfamiliar, an approval card shows the exact invocation. Deny skips that call. Stop ends the turn.

02

A model you already host

Quick Connect wants an endpoint, a key only if the server needs one, and a model with tool calling. Ollama is http://localhost:11434. LM Studio is often http://localhost:1234.

clio-coder configure
clio-coder targets --probe --tools

Chat and workers can use different targets. A local model for the edit and another model for the review is a normal arrangement, not an advanced mode. /model changes the session. Settings → Fleet changes the worker default.

03

Teach the project

The handbook is yours. The index is generated. Do not mix them.

clio-coder context init

Read the drafted CLIO-CODER.md. Keep build commands, conventions, and validation rules. Commit it. Runtime state belongs under .clio-coder/ and should stay out of the handbook. /context shows the window, the occupancy, and whether the prefix cache was reused.

04

A bounded change, then the checks you already have

Give the acceptance criterion in the request. Ask it to use verify, not a narrated “I ran the tests.”

The finite-difference step in solver.py is unstable at the current ratio.
Make the smallest change that the existing numerical test accepts.
Run that test. Do not reformat unrelated files.

verify knows pytest, unittest, Cargo, Go, CMake presets, Make, just, and scripts your CI already calls. It can compare numerical results and hold a performance budget. A green line is what ran. It is not a claim that the science is right.

05

A worker that is not allowed to write

The verifier recipe is the independent pass. Its ceiling is the lesson.

/run verifier Review the current diff and run the relevant existing checks. Do not edit files.

Workers run at default even if your session is yolo. A read-only dispatch is a restriction on top of that. Alt+W shows the board. ◇ means you asked. ◆ means the model asked.

06

Read the trust line

After the run, read the receipt instead of the last paragraph. You want five clauses, not a grade.

clio-coder fleet view <runId>
clio-coder evidence list
clio-coder evidence inspect <evidenceId>

Sealed means the bytes match. Grounded means a host check was observed. Not independently reviewed is a fact, not a failure of the printer. Unknown is a state. If a file changed and nothing validated it, the finish contract tells the model to call the change unverified.

07

Slurm, only if the kit is there

This lab stops if you do not have the clio-kit Slurm MCP server. Clio Coder does not invent a scheduler.

clio-coder mcp list

When the server is trusted, the slurm-jobs skill submits a batch script, polls to a terminal state, fetches output, and stamps the scheduler result. The kit’s own docs live at toolkit.iowarp.ai. A stamp is not a scientific conclusion.

08

Hand a task to an agent you already installed

Authenticate that agent first, with its own CLI. Then let Clio Coder see it.

clio-coder interop inspect --json
/interop
/delegate codex Review the proposed change and its edge cases.
/run --target opencode-local --worktree coder Fix the parser test and report the checks.

A worktree keeps the peer’s branch for review. It does not confine the peer’s own shell. Receipts mark that limit. OpenCode refuses a read-only headless run before launch. Use /share when the main session should read a managed result. The comparison is the argument. The guide is the contract.

09

Publish a procedure

When a workflow just worked, do not leave it in the transcript.

/skill workflow-distiller
clio-coder library validate ./path/to/package

Skills, agents, prompts, fleets, and plugins are different kinds. A command tool is an extension, not a skill. The authoring templates are in library/_authoring/templates/. The library page is the map.

What not to believe

Yolo is not an OS sandbox. A passing verify is not a paper. A worker’s summary is not a host check. A pane handoff has no receipt. The GUI is not the product. A film on this page, when one appears, is a demonstration, not a result.
