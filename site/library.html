Procedures, not chat logs

Write it
once.

The library is the canonical home of shareable packages. Every distributed byte is pinned. A peer host gets the real skill surface or it gets nothing. Clio Coder does not publish a package a peer would silently misread as a native agent.

Skill
/skill name. A procedure and its references.
Agent
/run id. Role, tools, budget, result contract.
Prompt
A slash command derived from the path. Arguments, not a hidden script.
Fleet
/fleet run. A DAG of agents, gates, and write boundaries.
Plugin
Several of the above, released together. Inspect it. Invoke the member you mean.

Materio

Materials plus I/O. A research question becomes a supplied-corpus literature synthesis, a feasible virtual lab, an assumption-driven task plan, inspected artifacts, and a reviewed paper handoff. The scientific workflow comes from Daisy Quach’s research system. The package separates that knowledge from host capabilities.

What peers load
Six portable skills. Claude Code reports skills, and zero native agents. The Clio Coder-only recipes travel in the bytes and are not presented as Claude agents.
What Clio Coder runs
Seventeen prompts, six agent recipes, and an execute-then-verify fleet whose host write boundary is .research/tasks/. A generated protocol is prepared work. Physical measurements remain pending human actions.
What it will not do
Initialize git to satisfy a fleet boundary. Pretend a verifier’s file read is scientific validation. Search the web because a setting was once named web_search. That flag means provided-URL retrieval and Crossref, and it defaults off.
clio-coder library install ./library/plugins/materio --project

Use it from the other side

claude plugin marketplace add iowarp/clio-coder
claude plugin install tdd@clio-coder
claude plugin install materio@clio-coder

For Codex, the repository’s .agents/skills links already point at the canonical trees. In any other checkout:

ln -s "$PWD/library/skills" ~/.agents/skills/clio-coder
ln -s "$PWD/library/plugins/materio/skills" ~/.agents/skills/materio

Nothing is converted. The marketplace file is generated from the pin registry. Hand-editing it is how the projection drifts from the bytes, so the check refuses that.

Author

Copy a template from library/_authoring/templates/. Templates are not catalog entries. Validate, pin, try in an isolated project, then open a pull request against the version branch, not an imaginary main-only workflow.

clio-coder library validate <package-path> --json
pnpm run library:pin
pnpm run library:check
