A clear boundary
around the engine.

Clio builds on the Pi agent framework while keeping product policy and scientific workflows in its own domains.

Session and context
A ledger retains observations; a working set selects what the model sees next. Session routing can differ from saved configuration.
Prompt assembly
Fragments compile into one prompt envelope that is hashed and reused byte for byte.
Typed tools
One registry admits reads, edits, commands, verification, and dispatch through the same policy path.
Model engine
Pi sits behind an engine boundary. Product domains do not import the vendor SDK directly.
Dispatch and evidence
Worker assignments specify role, node, ceiling, and result contract. Host checks and sealed records make the result inspectable.

Choose the right
extension point.

Extend a procedure, worker, workflow, or tool without patching the conversation loop.

Skill
A procedure in text with supporting references. Invoke it with /skill.
Agent
A worker recipe with a role, tools, budget, and result contract. Invoke it with /run.
Fleet
A workflow of workers, dependencies, gates, and write boundaries. Use /fleet run.
Plugin
A domain package of skills, agents, prompts, and fleets released together.
Extension
An executable Node or Python command tool with a schema, timeout, and digest. It remains subject to tool policy.

The browser is another
client of the runtime.

The alpha browser application connects to the same runtime as the terminal and headless CLI.

The GUI uses React/Vite in the browser. A Node/Hono service handles HTTP and server-sent events. The service connects to the Clio runtime through ACP over stdio.

Browser controls include conversations, attachments, session boards, context, fleet approval previews, usage and library access.
